# Aegis Redirection

Веб-панель для существующих Linux-шлюзов Xray + L2TP: каталог серверов и подписок,
независимый основной/резервный сервер для каждого интерфейса, мониторинг,
Telegram-уведомления и управление адрес-листами MikroTik.

## Обновление существующей ВМ

Начиная с 3.0.0 доступен раздел «Проверить обновление» под «Алерты».

## Удалённый доступ через ZeroTier

В версии 3.1.0 вкладка «ZeroTier» позволяет сохранить Network ID и подсеть,
затем установить клиент и подключить конкретную ВМ по явному действию.
Для настройки сети `10.241.0.0/16` укажите Network ID `12ac4a1e71c7267d`.
После подключения подтвердите появившийся Node ID в ZeroTier Central. Когда
Central назначит адрес, откройте панель по `http://<ZeroTier-IP>:8790`; ваш
компьютер также должен быть авторизован в этой приватной сети. Подключение
ZeroTier не меняет основной маршрут и не включает переадресацию трафика.
ZeroTier привязывается к выбранному локальному IP интерфейса ВМ. Во вкладке
ZeroTier выберите «Авто» для системного маршрута или конкретный адрес; чтобы
применить выбор к уже подключённому узлу, нажмите «Применить интерфейс».
Если устройство ожидает авторизации или адреса, кнопка «Переотправить запрос»
повторно подключит эту же сеть с прежним Node ID. Это повторяет обмен с ZeroTier,
но не заменяет разрешение устройства в Central.
Он показывает установленную и последнюю стабильную версии, описание релиза
и состояние установки. Блок версии внизу меню открывает тот же раздел.
Кнопка «Обновить панель» требует авторизации и запускает независимую службу
`aegis-panel-update`, которая переживает перезапуск сайта. Журнал находится
в `/opt/xray-gateway/updates/web-jobs/<id>/update.log`.

Первый релиз рассчитан на Ubuntu 22.04/24.04, Python 3.10+, systemd и существующую
установку в `/opt/xray-gateway`. Служба `manager.service` должна запускать
`/opt/xray-gateway/venv/bin/uvicorn app.main:app` из `/opt/xray-gateway/manager`.
Нужны `python3-venv`, `curl`, `iproute2`, `iptables`, Xray, xl2tpd и strongSwan.
Это обновление существующей ВМ, а не установщик чистого Linux.

В root-shell (`sudo -i`):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/DKardash/aegis-redirection/main/update.sh) --check
bash <(curl -fsSL https://raw.githubusercontent.com/DKardash/aegis-redirection/main/update.sh)
```

Или скачать скрипт и выполнить через sudo:

```bash
curl -fsSLo /tmp/aegis-update.sh https://raw.githubusercontent.com/DKardash/aegis-redirection/main/update.sh
sudo bash /tmp/aegis-update.sh --check
sudo bash /tmp/aegis-update.sh
```

`--check` скачивает релиз, создаёт отдельное Python-окружение, проверяет перенос
на копии базы и выполняет `xray -test`. Рабочие службы не останавливаются.
Для конкретной версии: `sudo bash /tmp/aegis-update.sh --version v1.0.0`.
Архив проверяется по SHA-256; источник доверия — HTTPS и аккаунт владельца
репозитория, а не независимая криптографическая подпись.

## Что сохраняется

- База серверов, подписок, настроек и паролей; `.env` и `SESSION_SECRET`.
- IP, L2TP-пользователи, назначения основных и резервных серверов каждой ВМ.
- Локальный `web/static/mikrotik-vpn-lists.rsc` и его резервные копии.
- Конфигурация MikroTik: обновление само по себе не отправляет на роутер списки.

В релизе нет пользовательской базы, токенов, паролей, адрес-листов или сетевых
конфигураций. Бинарник Xray обновлением панели не заменяется. Если новая версия
кода требует другой Xray, предварительная проверка остановит обновление.

Старая схема с общим активным сервером автоматически переносится в один
основной L2TP-профиль только при однозначно определяемых адресе, пуле и сервере.
Неизвестная/неполная схема останавливает обновление до замены кода. Дополнительные
IP, резервные серверы и пароли скрипт не придумывает. Для необычных старых ВМ
сначала используйте `--check` и предоставьте текст ошибки без секретов.

## Резервная копия и откат

Перед переключением скрипт останавливает панель, сохраняет согласованную SQLite
копию, предыдущий код и Python-окружение, файлы L2TP/Xray и таблицу mangle.
Xray/L2TP могут кратковременно перезапуститься при применении маршрутов.
Работоспособность проверяется по `/api/healthz`, версии и состоянию служб.
При ошибке включается автоматический откат. Старые и неудачные версии сохраняются.

Скрипт печатает путь транзакции и точную команду ручного отката, например:

```bash
sudo python3 /opt/xray-gateway/manager/scripts/updater.py --rollback ИМЯ_ТРАНЗАКЦИИ
```

Откатывается только последнее успешное обновление либо прерванная транзакция.
Откат восстанавливает и базу на момент обновления: более поздние изменения
настроек останутся в `failed-database` внутри транзакции, а не в рабочей базе.
После потери питания запустите команду отката из сохранённого каталога релиза,
если рабочий каталог ещё не восстановлен. Транзакции и окружения не удаляются
автоматически; учитывайте свободное место. Обновления нельзя запускать параллельно.

## Разработка и выпуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests
node tests/test_addresslists_ui.cjs
bash -n update.sh
python3 scripts/build_release.py
```

В `dist/` появятся `aegis-redirection.tar.gz` и `SHA256SUMS`. Сборка использует
список разрешённых типов и каталогов и не включает состояние ВМ.

Для нового релиза измените `VERSION`, обновите версию `app.js` в HTML, опишите
изменения в `CHANGELOG.md`, выполните тесты и отправьте тег `vX.Y.Z`. Workflow
проверяет код и прикладывает архив с контрольной суммой к GitHub Release.
Перед массовым развёртыванием проверьте `--check`, обновление и откат на копии
одной из старых ВМ. Новый релиз не устанавливается на другие ВМ автоматически.

## Ограничения первого релиза

Управление сетью требует root. Необычные пути службы, отсутствующая база,
неработающая служба manager и нераспознанная старая конфигурация требуют ручной
подготовки. Поддерживаются имена адрес-листов из букв, цифр, `_`, `-` и `.`.
Зависимости приложения закреплены по прямым версиям в `requirements.txt`;
транзитивные зависимости разрешаются pip при подготовке окружения.
